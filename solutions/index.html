Four places the series index gives up

Keep the tags. Keep the clients.

IoT fleets

Every sensor, every tick

Thousands to millions of devices, each with its own sensors. Temperature, humidity, vibration, and GPS arrive at high frequency. The tags that make the data useful — device ID, location, firmware, session — are the tags that used to force a cut.

  • Full resolution, queried with the InfluxQL you already use
  • Dashboards and anomaly checks stay on the same endpoints
  • No rewrite of the collectors already in the field
Read the IoT write-up

Observability

Labels that used to be too many

Pods, nodes, and services show up and disappear. Each one adds series: container, namespace, version, customer. Ingest spikes on deploy. The usual exit is fewer labels, or a database that only stays fast if you stop asking precise questions.

  • High-cardinality metrics, with the labels left on
  • Telegraf and Grafana stay as they are
  • Same /write your agents already speak
Read the observability write-up

Market data

Tick ingest, millisecond queries

Price, volume, and order-book updates, across thousands of instruments and accounts. Risk wants another dimension — counterparty, desk, asset class — and the query still has to come back while the market is the market.

  • Tick-level writes, InfluxQL for the read
  • GROUP BY time() for the windows you already chart
  • Historical ticks stay queryable, not only the last bucket
Read the market-data write-up

Energy systems

Grid telemetry at full resolution

Smart meters, inverters, turbines, and substations. Voltage, current, power quality, weather, and consumption, tagged by device, region, and asset type. Downsampling is a report. It should not be the only copy you keep.

  • Meter and asset identity stay on the series
  • High-frequency power and weather, written as measured
  • The same line protocol the existing collectors emit
Read the energy write-up

What they share

One wire. Four workloads.

None of these need a new agent or a new query language. They need the series you already wanted to store, on endpoints the stack already speaks. Sustained ingest on the measured box is 1.5 million points a second, p95 under 250ms.

  • +InfluxDB v1 line protocol on /write and InfluxQL on /query.
  • +Telegraf, Grafana, and the clients in the migration checklist.
  • +Continuous queries and master-master replication in the open-source binary.

Linear scale-out

Capacity tracks the number of shards, linearly. A Cloud shard is 4 CPU and 16GB. Add a shard, add the throughput again. Compute is $299 per shard. Disk is $0.20 per GB.
