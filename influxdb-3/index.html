InfluxDB 3

Keep the queries you already run.

InfluxDB 3 is a new database with a v1 compatibility layer. Core listens on port 8181, authenticates with a token, and by default a single query covers about 72 hours. InfluxQL is supported there, and InfluxData still lists parts of it as in progress. HyperbyteDB keeps line protocol and InfluxQL on /write and /query, on port 8086.

The move

What the new engine changes.

InfluxDB 3 Core

A compatibility layer

  • HTTP on port 8181. v1 username is ignored; the password is a token
  • Default query window of about 72 hours. The limit can be raised
  • SQL is the native language. InfluxQL is missing SLIMIT and SOFFSET
  • Retention policies are not how the data is stored. Flux is gone

HyperbyteDB

The v1 wire

  • Port 8086. Same /write and /query
  • InfluxQL, including the queries on the compatibility page
  • Replication, retention, and continuous queries in the Apache 2.0 binary
  • Plan on 1.5M points/sec sustained, p95 under 250ms

Those InfluxDB 3 details are from InfluxData’s own Core docs: the query guide, the query-file-limit setting, the v1 write API, and the InfluxQL support list. Which of your clients are only a URL change is on the checklist.

Questions

Before you pick an engine.

Does InfluxDB 3 still support InfluxQL?

Yes. InfluxDB 3 Core accepts InfluxQL, and InfluxData says the language is still being rebuilt for the new engine. SLIMIT and SOFFSET are not supported. HyperbyteDB speaks InfluxQL on /query. The differences are on the compatibility page.

What is the 72 hour limit?

InfluxDB 3 Core’s default query-file-limit is 432 Parquet files. With the default 10-minute blocks, that is about 72 hours in one query. The limit can be raised. HyperbyteDB does not use that cap.

Can I keep port 8086?

InfluxDB 3 Core listens on 8181 and expects a token. HyperbyteDB listens on 8086 and takes the same /write and /query calls. The client checklist says which tools are only a URL change.

How do I start?

Request early access for Cloud. The form is short. To self-host, pull ghcr.io/hyperbyte-cloud/hyperbytedb and listen on port 8086. No form.
